# REPS

ระบบแจ้งซ่อมและติดตามงานซ่อมอุปกรณ์คอมพิวเตอร์และระบบไอที สำหรับสถานศึกษา

REPS ช่วยให้ผู้ใช้แจ้งปัญหา ติดตามใบงาน และรับทราบความคืบหน้า ขณะที่ทีมสตาฟจัดคิวและบันทึกการซ่อม และผู้ดูแลตรวจสอบงาน รับรองงาน และดูรายงานได้จากระบบเดียว

## ความสามารถหลัก

- แจ้งซ่อมอุปกรณ์หรือระบบไอที พร้อมรายละเอียดและไฟล์แนบ
- ติดตามใบงาน ประวัติ และสถานะการดำเนินงาน
- จัดคิวและมอบหมายงานให้ทีมสตาฟ พร้อมบันทึกขั้นตอนการซ่อมและวัสดุที่ใช้
- รองรับการลงชื่อรับทราบและรับรองงาน รวมถึงสร้างใบรับรองงานสำหรับพิมพ์
- จัดการผู้ใช้และสิทธิ์ 3 ระดับ: ผู้ดูแลระบบ (`admin`), สตาฟ (`staff`) และผู้แจ้ง (`user`)
- จัดการสต็อกวัสดุ คะแนนสตาฟ และคำขอบคุณ Lab boy
- แสดงแดชบอร์ด ภาพรวมงาน และรายงานตามช่วงวันที่ ภาคเรียน หรือแผนก/งาน
- ปรับแต่งเนื้อหา หน้าเว็บ แบบฟอร์ม เมนู และรูปแบบเว็บไซต์ผ่านหน้าผู้ดูแล
- รองรับภาษาไทยและอังกฤษ

## เมนูผู้ดูแลระบบ

เมนูแบ่งเป็นกลุ่มตามงาน:

- **ภาพรวม:** แดชบอร์ดและภาพรวมงานซ่อม
- **งานซ่อม:** จัดการคำขอ รับรองงาน และดูประวัติ
- **ทีมสตาฟ:** จัดการภาคเรียนและทีม ดูคะแนน และคำขอบคุณ
- **ข้อมูล:** จัดการผู้ใช้ หน้าเว็บ แบบฟอร์ม และสต็อกวัสดุ
- **รายงาน:** สรุปตามช่วงวันที่ ภาคเรียน หรือแผนก/งาน

ส่วน **ตั้งค่าระบบ** และ **ปรับแต่งเว็บ** อยู่บริเวณด้านล่างของแถบเมนู เมนูที่แสดงอาจถูกปรับชื่อ ลำดับ หรือซ่อนได้จากหน้าปรับแต่งเว็บ ทั้งนี้การซ่อนเมนูไม่ได้เปลี่ยนสิทธิ์เข้าถึงหน้า

## เทคโนโลยี

- PHP 8 ขึ้นไป
- MySQL หรือ MariaDB โดยใช้ส่วนขยาย `mysqli`
- HTML, CSS, JavaScript
- Composer dependencies ที่รวมอยู่ใน `vendor/` เช่น mPDF และ FPDI สำหรับเอกสาร PDF

ส่วนขยาย PHP ที่ควรเปิดใช้งาน ได้แก่ `mysqli`, `mbstring`, `fileinfo`, `gd` และ `openssl` (การส่งอีเมลผ่าน TLS ต้องใช้ OpenSSL)

## เริ่มต้นใช้งาน

1. ติดตั้ง PHP และ MySQL/MariaDB บนเครื่องหรือเซิร์ฟเวอร์เว็บ และเปิดส่วนขยาย PHP ที่ระบุไว้ด้านบน
2. สร้างฐานข้อมูลโดยใช้ `utf8mb4` แล้วนำเข้า schema ตั้งต้นจาก [`database/scema.sql`](database/scema.sql) (ชื่อไฟล์ใน repository สะกดว่า `scema.sql`)
3. รัน migration ที่มีใน [`database/migrations/`](database/migrations/) ตามลำดับวันที่ หลังนำเข้า schema ตั้งต้น
4. ตั้งค่าการเชื่อมต่อฐานข้อมูลด้วย environment variables หรือไฟล์ `.env` ที่ `db_connect.php` อ่านได้:

   ```dotenv
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_NAME=reps_db
   DB_USER=your_database_user
   DB_PASSWORD=your_database_password
   APP_TIMEZONE=Asia/Bangkok
   APP_DISPLAY_ERRORS=false
   ```

5. ตั้งค่า web server ให้ document root ชี้ไปยังโฟลเดอร์โปรเจกต์ แล้วเปิดเว็บผ่านเซิร์ฟเวอร์ PHP/เว็บเซิร์ฟเวอร์ที่รองรับ PHP
6. สร้างหรือเตรียมบัญชีผู้ดูแลระบบในฐานข้อมูลก่อนเริ่มใช้งานจริง

อย่านำไฟล์ `.env` ที่มีรหัสผ่านหรือกุญแจ API ขึ้น GitHub ใช้บัญชีฐานข้อมูลแยกสำหรับแต่ละสภาพแวดล้อม และไม่ใช้ข้อมูลตัวอย่างเป็นบัญชี production

### การจัดเก็บไฟล์แนบ

ไฟล์แนบของใบงานควรเก็บนอก document root เพื่อไม่ให้เปิดไฟล์โดยตรงได้ ตั้งค่าตำแหน่งด้วย `TICKET_UPLOAD_DIR` และกำหนดให้ PHP เขียนลงโฟลเดอร์นั้นได้ ระบบให้บริการไฟล์ผ่าน endpoint ที่ตรวจสอบสิทธิ์

### อีเมลและงานตามเวลา (ตัวเลือก)

- ตั้งค่าการส่งอีเมลผ่านตัวแปรที่เกี่ยวข้อง เช่น `MAIL_TRANSPORT`, `MAIL_FROM`, `MAIL_USERNAME`, `MAIL_PASSWORD` หรือ `BREVO_API_KEY` ตาม transport ที่เลือก
- ตั้ง `APP_BASE_URL` หากต้องการให้ลิงก์ในอีเมลชี้กลับมายังเว็บไซต์
- `cron_queue.php` ใช้สำหรับเรียกตรวจและจัดการคิวตามเวลา โดยควรตั้ง cron บนเซิร์ฟเวอร์ให้เรียกตามช่วงเวลาที่ต้องการ

## โครงสร้างโฟลเดอร์

```text
admin/                  หน้าจัดการสำหรับผู้ดูแลระบบ
staff/                  หน้าทำงานของทีมสตาฟ
includes/               ระบบยืนยันตัวตน สิทธิ์ ใบงาน เมนู และส่วนที่ใช้ร่วมกัน
assets/                 CSS, JavaScript, ฟอนต์ และรูปภาพ
database/scema.sql      schema ตั้งต้นและข้อมูลพื้นฐาน
database/migrations/    การเปลี่ยนแปลงโครงสร้างฐานข้อมูลเพิ่มเติม
database/seeds/         สคริปต์และข้อมูลตัวอย่างสำหรับสภาพแวดล้อมพัฒนา
tests/e2e/              สคริปต์ทดสอบการทำงานแบบ end-to-end
```

## หมายเหตุ

- โปรเจกต์นี้ใช้ฐานข้อมูล MySQL/MariaDB และต้องนำเข้า schema กับ migration ให้ตรงกับรุ่นของโค้ด
- ก่อนเปิดใช้งานจริง ควรตั้งค่า HTTPS, รหัสผ่านและบัญชีผู้ดูแล, การสำรองฐานข้อมูล และโฟลเดอร์เก็บไฟล์ส่วนตัวให้เหมาะกับเซิร์ฟเวอร์
- รายละเอียดการเปลี่ยนแปลงระหว่างพัฒนาอยู่ใน [`docs/WORKLOG.md`](docs/WORKLOG.md)
